# 동네U

> **대전·충청권의 동네 가게와 사용자를 AI로 연결하는 로컬마켓 활성화 서비스**

## 📌 프로젝트 소개

**동네U**는 충청도 말투인 **“동네유~”**의 친근한 어감과,  
**동네 + You**라는 의미를 함께 담은 이름입니다.

동네U는 사용자의 **위치, 예산, 시간대, 상황**에 맞는 대전·충청권 로컬 가게를 추천하고,  
소상공인에게는 **AI 홍보도우미**를 제공해 지역 골목상권 방문을 유도하는 서비스입니다.

---

## 🎯 선택 주제

**경제: AI 기반 대전·충청권 로컬마켓 활성화 방안**

---

## 🧩 문제 정의

대전·충청권에는 좋은 로컬 가게가 많지만, 소비자는 보통 배달앱이나 지도앱의 광고 상위 노출, 리뷰 수, 프랜차이즈 중심 추천에 의존합니다.

그 결과 작은 소상공인 가게는 발견되기 어렵고, 소비자도 매번 비슷한 선택지만 보게 됩니다.

또한 소상공인은 홍보글, 메뉴 설명, SNS 문구를 직접 작성하기 어렵고, 광고비를 내지 않으면 플랫폼에서 노출되기 힘듭니다.

동네U는 이 문제를 해결하기 위해 소비자에게는 **상황 기반 로컬 가게 추천**을 제공하고, 소상공인에게는 **AI 홍보 도구**를 제공합니다.

---

## 💡 핵심 아이디어

동네U는 단순한 맛집 추천 앱이 아닙니다.

기존 배달앱이나 지도앱처럼 사용자가 직접 검색하고 많은 목록 중에서 고르는 방식이 아니라,  
사용자의 현재 상황에 맞춰 **동네 로컬 가게 3곳을 압축해서 추천하는 서비스**입니다.

또한 소상공인에게는 메뉴명, 가격, 특징 같은 최소 정보만 입력해도  
AI가 홍보 문구, 메뉴 설명, SNS 문구를 생성해주는 기능을 제공합니다.

---

## ✅ 핵심 해결 방향

1. 소비자의 “오늘 뭐 먹을까?” 고민을 줄입니다.
2. 광고가 아닌 위치, 예산, 상황, 로컬성을 기준으로 가게를 추천합니다.
3. 너무 많은 검색 결과 대신 추천 카드 3개로 선택지를 압축합니다.
4. 공공데이터를 활용해 대전·충청권 로컬 가게 후보를 구성합니다.
5. 소상공인에게 AI 홍보도우미를 제공해 홍보 부담을 줄입니다.
6. 착한가격업소, 전통시장, 한산한 시간대 등 지역 상권 활성화 요소를 추천에 반영합니다.

---

## 👤 사용자가 동네U를 써야 하는 이유

사용자는 정보가 부족해서 메뉴를 못 고르는 것이 아니라, 선택지가 너무 많아서 고르지 못합니다.

동네U는 사용자가 직접 검색어를 고민하지 않아도, 현재 상황만 입력하면 적합한 동네 가게 3곳을 추천합니다.

### 사용자 장점

- 검색어를 고민하지 않아도 됩니다.
- 광고 상위 노출보다 상황 기반 추천을 받을 수 있습니다.
- 추천이 3개만 나와서 빠르게 결정할 수 있습니다.
- 프랜차이즈가 아닌 숨은 동네 가게를 발견할 수 있습니다.
- 예산, 위치, 시간대, 혼밥/친구/데이트 같은 상황이 반영됩니다.
- 착한가격업소나 가성비 좋은 가게를 찾기 쉽습니다.
- 친구들과 메뉴를 고를 때 합의가 쉬워집니다.

---

## 🧑‍🍳 사장님이 동네U를 써야 하는 이유

소상공인은 좋은 가게를 운영하고 있어도 홍보에 어려움을 겪습니다.

동네U는 사장님이 메뉴명, 가격, 특징만 입력해도 AI가 자연스러운 홍보 문구를 만들어줍니다.

### 사장님 장점

- 메뉴명, 가격, 특징만 입력하면 AI가 홍보 문구를 만들어줍니다.
- SNS 문구, 앱 소개글, 메뉴 설명, 해시태그를 쉽게 만들 수 있습니다.
- 한산한 시간대 타임딜 문구를 생성할 수 있습니다.
- 홍보에 익숙하지 않은 소상공인도 쉽게 가게를 알릴 수 있습니다.
- 광고비 없이도 상황 기반 추천을 통해 노출 기회를 얻을 수 있습니다.

### 배민/요기요와의 차이

배민과 요기요는 주문과 배달 중심 플랫폼입니다.  
동네U는 주문이나 배달이 아니라, **지역 가게의 발견과 방문 유도**에 집중합니다.

### 네이버지도와의 차이

네이버지도는 사용자가 직접 검색어를 입력하고 많은 결과 중에서 선택해야 합니다.  
동네U는 사용자의 위치, 예산, 시간대, 상황을 바탕으로 추천 결과를 3개로 압축해 빠른 결정을 돕습니다.

## 🤖 AI 활용 방식

동네U는 복잡한 머신러닝 모델을 직접 학습시키기보다는,  
공공데이터와 규칙 기반 점수 계산을 활용해 추천 후보를 선정합니다.

AI는 추천 후보를 직접 고르는 역할보다는,  
사용자가 납득할 수 있는 **추천 이유**와 사장님을 위한 **홍보 문구**를 자연어로 생성하는 역할을 맡습니다.

## 🃏 추천 카드 구조

동네U는 단순히 추천 1, 추천 2, 추천 3처럼 보여주지 않고,  
각 추천 카드에 역할을 부여합니다.

### 오늘의 동네픽

| 카드명 | 의미 |
|---|---|
| 가까워U | 현재 위치에서 가까운 로컬 가게 |
| 아껴U | 예산에 맞는 착한가격/가성비 가게 |
| 새로워U | 평소 검색으로는 잘 안 보이는 숨은 동네 가게 |
| 살려U | 한산한 시간대 방문을 유도하는 골목상권 추천 |

MVP에서는 이 중 3개를 선택해 보여줍니다.

예시 구성:

1. 가까워U
2. 아껴U
3. 새로워U

## 🔎 음식점 탐색 방식

동네U는 사용자가 로컬 가게를 찾는 방식을 **AI 검색**과 **조건 선택 검색**으로 나누어 제공합니다.

사용자는 자연어로 원하는 상황을 입력해 AI에게 추천을 맡길 수도 있고,  
예산, 위치, 시간대, 분위기 같은 조건을 직접 선택해 원하는 기준으로 가게를 탐색할 수도 있습니다.

이를 통해 사용자는 “무엇을 검색해야 할지 모르는 상황”과  
“원하는 조건이 명확한 상황” 모두에서 동네U를 사용할 수 있습니다.

### AI 검색

AI 검색은 사용자가 원하는 상황을 자연어로 입력하면,  
AI가 문장의 의도를 해석해 적합한 로컬 가게를 추천하는 방식입니다.

예를 들어 사용자는 다음과 같이 입력할 수 있습니다.

```text
충남대 근처에서 혼자 먹기 좋고 만 원 이하로 든든한 저녁 추천해줘
```

```text
오늘 비도 오고 피곤한데 따뜻한 국물 있는 동네 가게 추천해줘
```

AI는 입력 문장에서 다음과 같은 정보를 추출합니다.

- 위치
- 예산
- 시간대
- 식사 상황
- 원하는 분위기
- 음식 선호
- 회피 조건

추출된 조건은 공공데이터와 가게 정보 필터링에 활용되며,  
동네U는 규칙 기반 추천 점수를 계산해 적합한 가게를 추천합니다.

AI는 단순히 결과만 보여주는 것이 아니라,  
사용자가 납득할 수 있도록 자연어로 추천 이유를 함께 제공합니다.

### 조건 선택 검색

조건 선택 검색은 사용자가 원하는 조건을 직접 선택해  
로컬 가게를 탐색하는 방식입니다.

AI 검색이 “알아서 추천해줘”에 가깝다면,  
조건 선택 검색은 “내가 원하는 기준으로 찾아볼래”에 가깝습니다.

사용자는 다음과 같은 조건을 직접 선택할 수 있습니다.

| 조건 | 예시 |
|---|---|
| 위치 | 충남대 근처, 대전역 근처, 둔산동, 유성온천역 근처 |
| 예산 | 7천 원 이하, 1만 원 이하, 1만 5천 원 이하 |
| 시간대 | 아침, 점심, 저녁, 야식 |
| 상황 | 혼밥, 친구, 데이트, 가족, 빠른 식사 |
| 선호 카테고리 | 한식, 분식, 중식, 일식, 카페 |
| 분위기 | 조용한 곳, 가성비, 든든한 메뉴, 새로운 곳 |
| 특수 조건 | 착한가격업소, 전통시장 근처, 로컬 가게 |

선택된 조건은 추천 점수 계산에 반영되며,  
동네U는 점수가 높은 가게를 추천 카드 형태로 제공합니다.

### 탐색 방식 비교

| 구분 | AI 검색 | 조건 선택 검색 |
|---|---|---|
| 사용 방식 | 자연어로 입력 | 조건을 직접 선택 |
| 적합한 상황 | 뭘 골라야 할지 모를 때 | 원하는 기준이 명확할 때 |
| 예시 | “비 오는 날 따뜻한 국물 추천해줘” | 위치, 예산, 상황, 카테고리 선택 |
| 장점 | 빠르고 편리함 | 기준이 명확하고 조절 가능 |
| 결과 설명 | AI 추천 이유 제공 | 점수 기반 추천 이유 제공 |
| 핵심 가치 | 검색어 고민 감소 | 선택 기준 직접 제어 |

### 추천 흐름

```text
사용자 입력
  ├─ AI 검색
  │   └─ 자연어에서 위치, 예산, 상황, 선호 조건 추출
  │
  └─ 조건 선택 검색
      └─ 사용자가 선택한 파라미터를 그대로 반영

공공데이터 기반 가게 후보 조회
  ↓
조건 필터링
  ↓
규칙 기반 추천 점수 계산
  ↓
추천 카드 3개 생성
  ↓
AI 추천 이유 생성
```

## 🛠 기술 스택 및 데이터베이스 설계

---
동네U는 하나의 코드베이스로 Android와 iOS에서 모두 동작할 수 있도록  
**Flutter**를 기반으로 개발합니다.

### 프론트엔드

| 구분 | 사용 기술 |
|---|---|
| 앱 개발 | Flutter |
| 개발 언어 | Dart |
| 지원 환경 | Android, iOS |
| UI 구성 | Flutter Widget 기반 |
| 상태 관리 | Provider 또는 Riverpod |
| 지도/위치 | 위치 권한, GPS 기반 위치 정보 활용 |
| API 연동 | Supabase SDK, AI API 연동 |

Flutter를 사용하면 Android와 iOS 앱을 따로 개발하지 않아도 되며,  
동일한 기능과 화면을 두 플랫폼에서 빠르게 구현할 수 있습니다.

### 백엔드 및 데이터베이스

| 구분 | 사용 기술 |
|---|---|
| 백엔드 서비스 | Supabase |
| 데이터베이스 | Supabase PostgreSQL |
| 사용자 인증 | Supabase Auth |
| 파일 저장 | Supabase Storage |
| 서버 로직 | Supabase Edge Functions |
| 실시간 기능 | Supabase Realtime |
| 권한 관리 | Row Level Security |

사용자 정보, 가게 정보, 메뉴 정보, 추천 기록, 사장님 홍보 문구 등을 저장하는 데 사용합니다.

## 🔐 권한 관리 계획

Supabase의 Row Level Security를 사용해 사용자 권한을 관리합니다.

| 대상 | 권한 |
|---|---|
| 일반 사용자 | 가게 조회, 추천 요청, 즐겨찾기, 리뷰 작성 |
| 사장님 | 본인 가게 등록 및 수정, 메뉴 관리, AI 홍보 문구 생성 |
| 관리자 | 공공데이터 관리, 부적절한 정보 수정, 전체 데이터 관리 |

### 기본 권한 원칙

1. 모든 사용자는 가게 정보를 조회할 수 있습니다.
2. 일반 사용자는 자신의 추천 기록과 즐겨찾기만 조회할 수 있습니다.
3. 사장님은 본인이 등록한 가게와 메뉴만 수정할 수 있습니다.
4. AI 홍보 문구는 생성한 사장님만 조회하고 관리할 수 있습니다.
5. 공공데이터 기반 가게 정보는 관리자만 직접 수정할 수 있습니다.

## 🧮 추천 로직 구성

동네U의 추천은 Supabase에 저장된 가게 정보와 메뉴 정보를 바탕으로  
규칙 기반 점수를 계산해 상위 가게를 선정합니다.

| 항목 | 점수 |
|---|---:|
| 거리 적합도 | 20점 |
| 예산 적합도 | 20점 |
| 상황 적합도 | 20점 |
| 메뉴 선호도 | 15점 |
| 로컬 가게 여부 | 15점 |
| 착한가격업소 여부 | 10점 |

총점이 높은 가게 중에서  
사용자 상황에 맞는 추천 카드 3개를 생성합니다.
